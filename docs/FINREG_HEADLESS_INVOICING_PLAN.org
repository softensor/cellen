#+TITLE: Cellen ↔ FinReg — Headless Invoicing Plan
#+DATE: 2026-11-27
#+STATUS: Accepted 2026-11-27; phases 1–6 implemented — see FINREG_HEADLESS_ROLLOUT_RUNBOOK.org

* 1. Goal

Cellen becomes the *only* interface a school ever sees. FinReg stays the fiscal
authority (numbering, tax totals, AGT signing, SAF-T, official PDFs) but works
entirely in the background, server to server. No "Abrir no FinReg", no second
login, no FinReg screens.

One line: /Cellen owns the experience, FinReg owns the legal truth./

* 2. Where we are today

Most of the background plumbing already exists:

| Concern                     | Already in Cellen                                                        |
|-----------------------------+--------------------------------------------------------------------------|
| Issue (billing run)         | ~/billing/runs~ → ~FinregBillingInstruction~ outbox → FinReg              |
| Issue (ad hoc)              | ~POST /finreg/sales/preview~, ~POST /finreg/sales/issue~                  |
| Payments / corrections      | ~POST /finreg/payments~, ~POST /finreg/documents/{ref}/corrections~       |
| Document + PDF              | ~GET /finreg/documents/{ref}~, ~/pdf~                                     |
| Parent side                 | ~/finreg/parent/documents~, ~/receipts~, ~/statement~ (already native)    |
| Idempotent retry            | ~/finreg/instructions/{id}/retry~, same idempotency key                   |
| Event sync                  | ~app/services/finreg_events.py~ polls FinReg ~GET /integrations/events~   |

*The redirect is limited to six admin routes* in ~mobile/lib/core/router/router.dart~,
all rendered by ~FinregSalesHostScreen~ → ~POST /finreg/workspace-launch/{capability}~:

| Cellen route                   | Launches FinReg workspace |
|--------------------------------+---------------------------|
| ~/admin/finance/invoices~      | billing                   |
| ~/admin/finance/credit-notes~  | billing                   |
| ~/admin/finance/receipts~      | payments                  |
| ~/admin/finance/statement~     | receivables               |
| ~/admin/finance/saft~          | reporting                 |
| ~/admin/finance/audit-log~     | reporting                 |

So this project is mainly *replacing six launcher routes with native screens*,
plus a local document ledger so those screens are fast and work offline from
FinReg's UI.

* 3. Target architecture

#+begin_example
  Cellen app (admin / parent)
        │  only Cellen UI, Cellen auth, Cellen roles
        ▼
  Cellen backend
    ├─ business intent: propina, matrícula, multa, pagamento
    ├─ outbox (FinregBillingInstruction) ── idempotent ──► FinReg integrations API
    ├─ FinregDocument ledger  ◄── events poller (GET /integrations/events)
    └─ PDF proxy (stream from FinReg, never re-render)
                                                         FinReg
                                                           ├─ numbering, series, tax
                                                           ├─ AGT submission / signature
                                                           ├─ official PDF
                                                           └─ SAF-T
#+end_example

Invariants (unchanged):
- Cellen never calculates tax, numbers or totals. It shows what ~preview~ returns.
- Every fiscal mutation goes through the outbox with a stable instruction UUID.
- FinReg API scope/tenant/capability enforcement stays authoritative.
- Sandbox and production remain strictly separated.

* 6. FinReg-side changes needed

| Gap                                                     | Why                                                       | Proposal                                              |
|---------------------------------------------------------+-----------------------------------------------------------+-------------------------------------------------------|
| No AGT status event                                     | Cellen can't show accepted/rejected without polling       | emit ~document.agt_status_changed~ with reason code   |
| No integration document list                            | ledger backfill / reconciliation                          | ~GET /integrations/documents?since=&kind=~ (paged)    |
| No integration audit endpoint                           | audit-log screen can only show Cellen-side history        | optional; Cellen-side history is enough for v1        |
| PDF branding inputs                                     | school logo on official PDF                               | tenant branding fields settable via provisioning API  |
| Receipts list per tenant                                | receipts screen backfill                                  | covered by the document list with ~kind=RC~           |

FinReg remains a separate product (rule 1); these are additions to its public
integrations API, versioned through ~finreg-kit~ (rule 4).

* 7. Acceptance criteria
- A school admin can, without ever leaving Cellen: run monthly billing, see every
  invoice with its AGT status, open/share the official PDF, register a payment
  and get the receipt, correct or void an invoice with a credit note, view a guardian
  statement, and export SAF-T for a month.
- No Cellen screen, link or email points to a FinReg URL.
- Every fiscal number, total and PDF shown in Cellen comes from FinReg.
- Killing FinReg mid-operation leaves an instruction that, once FinReg is back,
  completes with the same identity (no duplicates).
- Sandbox school data never reaches production FinReg, and vice versa.

* 8. Open questions
1. *ERP add-on*: schools with the full FinReg ERP (accounting, payables,
   inventory) — keep a launcher only for them, or offer the ERP as a separate
   FinReg product with its own login? Recommendation: separate login, keep Cellen
   free of any launcher.
2. *Certified-software mention*: the official PDF most likely needs to show
   FinReg's AGT software certification line. Confirm the exact wording against
   the AGT rules. This is expected and fine: FinReg is invisible in the UI, not on
   the legal document.
3. *Local ~Invoice~ model* (~app/models/finance.py~): for schools in
   ~disabled~ mode Cellen still issues internal, non-fiscal invoices. Keep both
   paths, but make the native screens show the FinReg ledger whenever the connection
   is ~pilot~/~live~, and label internal documents as non-fiscal.
4. Event delivery: polling is enough for v1; consider FinReg → Cellen webhooks
   later for lower latency.
